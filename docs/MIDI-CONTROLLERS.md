# External MIDI controller setup

**What works:** FM1 Studio receives standard MIDI from keyboards, pad controllers and control surfaces exposed by Android. Basic note input does not require a dedicated device profile. Keys send pitches, pads usually send notes, and knobs/buttons work according to the MIDI messages they actually emit. Check your controller's manual for its connection modes and programmable controls. An M-VAVE SMK-37 is one possible keyboard example, but it is untested with this app; it has no dedicated profile or confirmed hardware test in this repository.

**Connect:** Open **Menu → MIDI / AUDIO / FILES → Connect USB / available MIDI** after connecting the keyboard to Android with a USB data cable and an OTG adapter if needed. Select it in the input list. For a controller offering Bluetooth LE MIDI, use **Connect Bluetooth LE MIDI**, grant the requested Bluetooth permissions, and select it there; Bluetooth pairing alone does not open a MIDI connection. The app selects one input device at a time. A controller using a proprietary wireless receiver needs that receiver to appear to Android as a MIDI device.

**Play and record:** Choose **MIDI routing and pad notes → Selected track**, select a synth track, and play. No key learning is needed: a MIDI C plays that pitch, and incoming velocity controls the note's strength. For independent channel routing, choose **Original channels** and match the controller's channel to the firmware's track settings; the common SLOOP default is channels 1–3 for synths and 10 for drums, while other engines differ. Arm recording using the app's recording controls and start the appropriate recording mode to capture notes into the pattern. Use **STEPS** to inspect and edit the result on engines with the shared piano roll. External keys play/record notes; they do not select or drag piano-roll cells, and a hardware Record button is not automatically assigned to the app's recording action.

**Drum pads:** Pads sending the firmware's expected drum-note numbers can play its lanes directly. If your pads send consecutive notes, select **Drums** routing, then open **Pad notes** and enter the first pad's MIDI note number, such as 36. The consecutive input range maps to the selected firmware's declared drum lanes; **-1** preserves the incoming note numbers for the firmware's normal drum mapping. This is a manual base-note setting, not individual pad learning. For a scattered pad layout, program the pad notes on the controller if its editor supports that. Selected-track routing does not apply this generic pad-range conversion.

**Knobs and faders:** By default, CC messages reach the firmware's standard parameter mappings. For page-following controls, open **MIDI knobs → FM-1**, choose an absolute or supported relative format, enter the first CC of a seven-consecutive-CC range, and select the MIDI channel (or any channel). Those seven controls operate **SELECT, ALGO, PRESETS, K1–K4**, in that order; only controls sending that range are mapped. For example, program seven knobs to CC 20–26 and enter 20. Absolute mode uses movement, with the first value establishing a baseline; relative mode is preferable when the controller supports it. This mapping intercepts those CCs, replacing their standard parameter actions.

**Parameter learning:** SLOOP and Felucca expose **Menu → Instrument Settings → MIDI LEARN**. Choose a parameter in the learning sheet, then move the external knob or fader sending the CC you want to assign. Repeat for other parameters and select **DISABLE LEARN** when finished; assignments are saved with the firmware's settings. Alternatively, enable learning, adjust a sound parameter in the app, then send the controller CC. Keep **MIDI knobs → FM-1** off, or use CCs outside its intercepted range, when learning parameter assignments. This learns CC-to-parameter mappings, not key-to-pitch or button-to-app-action bindings; reserved CCs may be rejected. Other currently included firmware profiles do not expose this Android learning sheet.

**Buttons and controller programming:** Generic controller buttons are not automatically mapped to Play, Stop, Record, page navigation or piano-roll editing. They work only where their actual note, CC or other MIDI message is handled by the selected firmware; a note-sending button may simply play a note. There is no generic “press a button to learn an app action” feature or arbitrary per-key note remapping yet. Use the app's touch controls for those actions, and configure outgoing notes, CCs and channels in the controller's own editor where supported; consult the manufacturer's manual and support/downloads page for your exact model. **JP-1 controller mapping** learns JP-1 controls only and is gated by JP-1 device recognition, so opening it does not make other controllers' buttons learnable. Generic MIDI preferences are stored per firmware; JP-1 assignments are shared across firmware choices.

## Ghoulbox and zp12

| Mapping | Ghoulbox | zp12 |
| --- | --- | --- |
| Original MIDI notes | Channels 1–4 address tracks 1–4 by default; the firmware can select other channel blocks. | Notes 36–67 play A1–D8 on any channel. |
| Selected-track routing | Routes incoming channels to the selected track, retaining note-off ownership across track changes. | Pads have fixed note numbers and output channels; changing MIDI channel does not select a different sound. |
| Program Change | Follows upstream behavior; this adapter adds no program-to-project mapping. | 0–15 selects loop 1–16, queued at the loop boundary during playback. |
| Standard controllers | Upstream fixed CC map, including CC7 level, CC10 pan, CC64 sustain, bend, CC21–24 engine controls, effects and tape. MIDI learn is not exposed for this firmware. | No upstream fixed sound-parameter CC map. Use **MIDI knobs → FM-1** for the seven native encoders or the JP-1 profile. |
| Realtime transport | Set the native clock source to USB MIDI for raw Start/Continue/Stop and MIDI clock. JP-1 transport also works with the internal clock. | Raw Start/Continue/Stop and JP-1 transport control the internal-clock sequencer. MIDI clock synchronization and MIDI output are not implemented by this adapter. |

**JP-1 on Ghoulbox:** The normal synth/drum mapping applies. Synth Play mode keeps its two octave pads; the eight DRUM lanes use their native GM notes, with CRYPT kit names shown when appropriate. Bank A controls the current page, B the selected sound page, and C pattern length/division/swing/gate. Bank C uses explicit pattern metadata, independently of the currently displayed native page. Stop releases notes and latched drones; note-offs retain their original target when changing tracks.

**JP-1 on zp12:** Auto plays sounds even with the keyboard hidden. All 16 pads work: JP pad bank A plays native A1–B8, B plays C1–D8, and C repeats A1–B8. Pads do not become octave controls. The knob bank and pad bank remain independent. Previous/Next and the second knob select among all 32 pads; BT mutes the selected pad's output channel. Play toggles transport, Stop silences voices, and a second REC press cancels an armed recording. Knob banks A/B/C provide current-page/sound/loop settings with absolute-value pickup and target-stable parameter IDs. Readouts follow the native settings; unavailable knobs and destructive COPY/CLEAR/RESET actions are excluded from absolute parameter mappings and remain available through the native panel's confirmation workflow.

Explicit **Steps** mode on zp12 toggles the currently selected sound on the 16 subdivisions of the native step bar (`SEQ` held + `OCT−`/`OCT+` chooses the bar). This edits the native sequencer without opening the shared piano roll. Feedback uses the selected sound's hits, active native pads and their actual output-channel mute/solo state. Standard CC-to-encoder mapping still operates SELECT/ALGO/PRESETS/K1–K4 directly, including native page-specific behavior.
